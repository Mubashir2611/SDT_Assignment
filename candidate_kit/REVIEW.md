# Starter review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Treats the punch's existing timezone/date as the shift's IST date; MongoDB datetimes are UTC and overnight attendance may belong to the prior date. | A UTC-stored punch at 04:35Z for a 09:30 IST shift is evaluated against the wrong wall clock. | Convert instants to IST and use the calculated attendance date as the shift-start date. |
| 2 | `compute_late_minutes` | Does not truncate fractional seconds before applying the 10-minute grace threshold. | 09:40:00.900 should be on time, but the starter treats it as late. | Truncate instants to whole seconds before all calculations. |
| 3 | `compute_late_minutes` | Does not account for an overnight attendance date when evaluating shift start. | A 01:00 punch on a 22:00-06:00 shift is compared with the wrong calendar day's 22:00. | Use the R1 attendance day to anchor the shift start. |
| 4 | `compute_work_hours` | Python `round` uses ties-to-even and floating-point arithmetic, not R4 half-up rounding. | A duration exactly halfway at the hundredth-hour boundary can round down unexpectedly. | Calculate from whole seconds with `Decimal` and `ROUND_HALF_UP`. |
| 5 | `compute_work_hours` | Does not normalize/truncate the two instants before subtraction. | Fractional BSON seconds change a boundary result. | Normalize both instants to UTC whole seconds first. |
| 6 | `compute_overtime` | Builds every shift end on the attendance date, even for overnight shifts. | A 22:00-06:00 shift's end must be on the next calendar day. | Advance the shift-end date when `shift_end <= shift_start`. |
| 7 | `compute_overtime` | Counts any positive overtime instead of requiring at least 30 whole minutes. | A punch-out 29:59 after shift end should yield zero. | Floor elapsed seconds to minutes and return zero below 30. |
| 8 | `compute_overtime` | Compares a naive punch-out with an IST-aware shift end, which can raise `TypeError`; it also assumes the input is already in IST. | Punch-out values read from default PyMongo settings are naive UTC datetimes. | Use timezone-aware UTC values and convert to IST for comparison. |
| 9 | `/health` | Always reports success without checking MongoDB. | Stop MongoDB and `/health` still returns 200. | Ping MongoDB and return 503 when it cannot answer. |
| 10 | `create_employee` | The duplicate check is a check-then-insert race and there is no unique database constraint. | Parallel creates with one `emp_code` can both pass the check. | Create a unique `emp_code` index and translate duplicate-key errors to 409. |
| 11 | `create_employee` / `EmployeeIn` | Employee fields, code format, dates, shift times, and equal shift bounds are not validated. | Malformed `joined_on`, invalid shifts, or an invalid email can be stored. | Add typed request validation for the contract. |
| 12 | `create_employee` | Stores naive `created_at` and returns it as a datetime rather than epoch milliseconds. | The response violates the instant representation and timezone convention. | Store UTC-aware time and serialize it to integer epoch milliseconds. |
| 13 | `list_employees` | Omits the required `emp_code` ascending sort and does not constrain page/page_size. | Repeated pages can be unstable; page 0 or an oversized page is accepted. | Sort by code and validate page bounds (page_size 1-100). |
| 14 | `punch_in` | Dereferences a missing employee, producing 500 rather than 404. | Punch in with an unknown code. | Return 404 before reading shift fields. |
| 15 | `punch_in` | Accepts unvalidated timestamps/statuses, uses local-time `fromtimestamp`, and does not truncate the punch instant. | Send seconds, a float, an unsupported status, or fractional milliseconds. | Validate integer epoch milliseconds and presence status; convert from UTC and truncate. |
| 16 | `punch_in` | Computes attendance date as the timestamp's local date and has no duplicate-safe insert constraint. | Punch in after midnight during an overnight shift, or send concurrent duplicate requests. | Calculate the IST attendance day and rely on the unique `(emp_code, date)` index, mapping duplicate key to 409. |
| 17 | `list_attendance` | Reads and sorts the entire collection in Python, so it does not scale to 100k logs. | Latency and memory use grow with the whole collection, even for one page. | Count filtered records and sort/skip/limit in MongoDB using indexes. |
| 18 | `list_attendance` | Does not validate date range or pagination and returns MongoDB `_id`/datetime shapes instead of the contract response. | Invalid dates/ranges pass through; response leaks internal id and uses ISO datetimes. | Validate inclusive date bounds and page limits; explicitly serialize only public fields and epoch milliseconds. |

**Reviewed and not defects:** `compute_late_minutes`'s intended strict `> 10` grace comparison and the starter's inclusive `$gte`/`$lte` date filters match the contract once timezone handling and input normalization are corrected. The existing route names and basic filtered `total` semantics are also correct.
